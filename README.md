# 兴文高铁站专线 · 司机台账

适合手机操作的专线车预约及收入管理应用，支持添加到桌面、离线登记和多人同步。

需要自行调整人数、同步频率、预约量和时间速度进行仿真时，运行 `npm run simulator`，打开 <http://127.0.0.1:9340/>。参见 [仿真实验室使用说明](docs/SIMULATOR.md)。

- 应用地址：https://liziyaaa.github.io/dashi-shuttle/
- 应用代码：https://github.com/liziyaaa/dashi-shuttle
- 私有数据仓库：https://github.com/liziyaaa/dashi-shuttle-data

## 日常使用

1. 默认查看今天全部班次的乘客；选择日期、行车方向。点班次只看该班，再点同一班次回到手机本地今天的全部班次。
2. 接到乘客电话后点「新增预约」，填写地点、具体上车点、电话和人数。
3. 接到乘客后点「标记上车」；实际收到钱后再点「收款」。手机号可直接点击拨号。
4. 「收入统计」显示每班实收、全天实收及待收款。未登记预约的临时乘客，可点「补记收入」。
5. 更换手机、清除浏览器数据前，先确认设置中显示「已同步」。每日收入可以在收入统计中导出 CSV。

班次为 07:00—21:00，每小时一班，包含 21:00，共 15 班 / 方向；两个方向暂用同一时刻表。班次时间是始发站发车时间，不是途中到站时间。

默认票价：马岭 → 高铁站 40 元 / 人、江门 → 高铁站 20 元 / 人、高铁站 → 大石 60 元 / 人。大石去程票价尚未确认，默认 0，录入预约时请按实际票价修改。每笔预约都可单独调整票价。返回方向默认从高铁站上车，可在具体上车点及备注中填写接人信息。

## 多人同步

GitHub Pages 托管公开的程序，乘客电话和收入只存于手机本地及另一个**私有**数据仓库，不写入本公开仓库。每个司机的设备都需要配置连接。未连接时仍可单机使用，但不同手机不会自动同步。

### 首次连接（仓库所有者操作）

1. 打开 GitHub 的 [创建细粒度令牌](https://github.com/settings/personal-access-tokens/new) 页面。
2. 名称可填 `Xingwen Shuttle`，资源所有者选择 `liziyaaa`，设置合适的过期时间。
3. Repository access 选择 **Only select repositories**，**只选 `dashi-shuttle-data`**。
4. Repository permissions 中将 **Contents** 设为 **Read and write**，其余保持默认；Metadata 的读取权限由 GitHub 自动授予。
5. 生成后复制令牌。在应用「设置」中仅粘贴连接密钥，点「连接并同步」。仓库固定为 `liziyaaa/dashi-shuttle-data`，无需司机填写。
6. 在其他司机手机的桌面应用中填写管理员提供的受限令牌，确认显示「已同步」。共享令牌的司机拥有相同的数据权限；撤销该令牌会同时断开使用它的设备。需要按人撤销时，应为不同司机分别生成受限令牌。

令牌是访问私有乘客数据的钥匙，只保存到使用设备的浏览器存储中；不会进入 JSON 备份、应用代码或公开仓库。请通过私密渠道配置给信任的司机。**不要填写当前电脑 gh CLI 使用的广泛权限令牌，也不要使用 classic PAT**。到期前更换受限令牌，换令牌不影响台账。程序不会代替你在公开仓库中保存任何 GitHub 凭证。

### 同步规则

- 本机立即保存；首笔待上传修改后 30 秒合并上传，后续修改不重置这批截止时间；页面可见且未打开录入弹窗时每 120 秒检查一次；恢复网络、返回页面时优先同步未上传内容；服务限流期间遵守等待时间。
- 断网期间先写本机。网络恢复后将记录合并到云端；也可在台账或收入页点击「立即同步」，立即上传并刷新。
- 新增预约用唯一编号，不同司机新增的记录会合并。同一编号同时修改时，保留更新时间较新的整条记录；手机时间应保持自动校准。对同一预约的编辑请尽量由一位司机完成。
- 删除会留下删除标记，避免其他手机把已删除记录重新传回来。GitHub 更新冲突会重新读取并最多重试 4 次。
- 手机仍有未上传记录时，请先确认同步成功再清理数据。更换密钥保留本机数据。
- 不具备车辆分配、司机独立账单或座位锁定功能。当前所有司机共用整条专线的一份台账与收入。
- 此方案适合小规模司机团队。GitHub API 存在请求限额；数据文件也会随台账增长。长期大量使用时可迁移到专用数据库，保留现有手机界面。

## 收入规则

使用整数「分」保存金额，避免浮点数误差。

- 预约应收 = 有效预约的每人票价 × 人数。
- 实收 = 已标记「全额收款」的有效预约金额 + 补记实收。
- 待收 = 尚未全额收款的有效预约金额。
- 取消 / 删除预约不计人数和收入。取消已收款预约前会提醒核实退款，本应用不执行退款。
- 未设置部分收款；若有特殊情况，在备注中记录并按实际金额调整。
- 「补记收入」只用于预约以外的实际收入，避免与已收款预约重复计入。
- 日期按手机本地日期，默认面向中国时区使用。

## 添加到手机桌面

- iPhone：Safari 打开应用地址 → 分享 → 添加到主屏幕。
- Android：Chrome / Edge 打开应用地址 → 菜单 → 安装应用 / 添加到主屏幕。

建议先安装，再在桌面应用内连接云台账：独立桌面应用和浏览器标签页可能使用不同的存储。首次完整加载页面且离线资源缓存完成后，可断网打开并登记。尚未设置密钥时，离线记录仅在本机。部分安卓浏览器可能只提供桌面快捷方式。

页面具有 manifest、192 / 512 图标、Apple touch 图标和 Service Worker；所有资源采用相对路径，支持 GitHub Pages 的项目子目录。缓存按版本升级；发布代码时应同时递增 `sw.js` 中的缓存版本。启动应用、返回前台和恢复联网时会检查新版本，并显示「立即更新 / 稍后」提示。新资源全部缓存完成后，点击「立即更新」才切换版本，正在填写预约时需先保存或关闭表单。更新保留本机记录与连接设置，离线时仍使用当前版本。当前版本不会因为同版本的待激活缓存而显示更新提示。

## 备份与隐私

管理员可在私有数据仓库中下载 `ledger.json` 备份，内容包含全部日期、联系方式、备注及收款情况，请妥善保管。司机设置页只提供连接密钥，不再展示备份、票价、安装及开发配置。CSV 仍可从收入统计中导出，仅包含选定日期的往返收入汇总，不包含电话。

清理浏览器数据、卸载应用、使用无痕浏览可能丢失本机数据；请先确认同步完成；尚未上传的离线记录需要保留原设备。私有仓库及历史提交会保留曾经上传的数据，删除当前记录并不抹除 Git 历史。

## v1.3.0 批量同步与历史归档

- 本机记录和待上传队列在一次 localStorage 写入中同时保存，刷新或关闭后不丢待同步状态。
- 首笔待上传修改后 30 秒上传一批，连续修改不延后原定截止时间。同步期间新增的修改由下一批处理；手动「立即同步」立即处理上传和下载。
- 前台每 120 秒自动刷新。未到上传时间的批次遇到轮询只拉取，不提前上传。无变动的常规轮询只读取活跃文件；仓库私有状态读取校验缓存 10 分钟，每次实际写入前重新校验。
- 活跃范围为手机本地日期往前 14 天（含边界日）及全部未来预约。日期边界只能前移，避免旧手机把历史数据重新加入活跃文件。
- 云端 `ledger.json` 自动升级为 schema 2 / protocol 2，含截止日期和月归档索引。本机数据保持 schema 1，附带 `_sync` 持久队列及归档缓存信息。**所有司机都应升级到 v1.3.0；旧版遇到 schema 2 会拒绝继续同步，已有本机记录保留，升级后继续合并。**
- 历史文件位于 `archives/YYYY-MM.json`，先成功保存月归档，再以 SHA 校验更新活跃文件。任何中断或冲突都不先删除唯一副本；重试采用合并而非整份覆盖。
- 每条记录保留不变的 `homeMonth`（初次乘车月份）用于定位历史文件。修改乘车日期后，在归档索引登记目标月份；按乘车日期查看时自动加载相关文件，按 id 合并，不重复计入收入。旧版迁移时记录有限的历史位置映射。
- 日期明确的删除标记随所属月份归档；旧版无乘车日期的删除标记继续保留在活跃台账中，以免旧记录复活。
- 选择两周前的日期自动按月读取并缓存历史；离线显示已有缓存。普通同步不会上传整份本地历史缓存，只有明确待同步的修改参与上传。
- 限流遵守 Retry-After / 额度重置时间，其他失败使用逐步延长的重试等待。iOS 后台计时器可能暂停，重新打开时继续同步；关闭应用前如急需共享请点「立即同步」。
- 测试均使用模拟私有数据接口，不对真实乘客数据做压力写入。Playwright 使用时钟模拟验证真实的 30 秒/120 秒生产间隔，不缩短应用参数。

### 后续版本发布

发布时同时更新 `package.json` / `package-lock.json`、`version.json`、`updates.js` 的 `APP_VERSION`、`sw.js` 的 `VERSION`，以及 HTML、manifest 和模块 import URL 的版本号，再运行 `npm test` 检查一致性。`version.json` 不进入离线缓存。

从 v1.1 升级的首次操作：用 Safari 打开 `https://liziyaaa.github.io/dashi-shuttle/?v=1.2.0` 并刷新，完整加载后关闭并重新打开桌面应用。旧版没有提示更新的代码，首次需要手动刷新；后续版本由应用提示更新。无需清除浏览器数据。
