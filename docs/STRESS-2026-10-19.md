# 2026-10-19 压力测试记录

本轮使用真实应用 UI、独立司机浏览器环境、模拟 GitHub 文件接口与共享账号配额模型。没有向真实 GitHub 施加压力，没有读取或修改真实乘客台账。只读检查了当前 GitHub 连接的配额，返回 `limit: 5000`；没有把这个连接的实时余额自动当作应用所有司机的初始条件。

## 20人200笔的受控对比

三轮均为相同种子、20分钟业务过程、8分钟自动收尾：新增200笔、收款200次、上车200次、备注修改65次、取消14次，未覆盖操作为0。已逐项核对：前两轮配置完全相同；第三轮仅修改上传和刷新间隔，没有提高额度或降低操作量。

| 业务版本与间隔 | API请求 | 写入尝试 | SHA冲突 | 限流响应 | 云端预约 | 待上传 | 结果 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| v1.3.3，上传30秒 / 刷新120秒 | 1480 | 427 | 230 | 11 | 105 | 110 | 二级限流后错误等待到小时重置 |

| v1.3.4，上传120秒 / 刷新300秒 | 1048 | 303 | 149 | 0 | 200 | 0 | 自动一致，20台全部收敛，无需手动恢复 |

后两轮的预约及全部修改在本机保留检查均通过；限流后提前重试均为0。第三轮预期实收与云端实收同为13580元。增加合并间隔显著降低请求和冲突，但会增加跨手机看到修改的等待，不能只追求最低请求量；正式应用仍采用30秒 / 120秒。

这里的“500次”是保守模型对获准执行的PUT尝试（包括冲突）计数，**不是测得 GitHub 在这组真实流量下必然限流**。复测目录分别为 `stress-2026-10-19T04-20-30-778Z` 和 `stress-2026-10-19T04-27-10-237Z`，汇总是派生视图，原始批次未改动。v1.3.4原始摘要同时保存应用版本和业务源码SHA256指纹。

## 已修复：二级限流错误等待到小时重置

峰值场景触发11次二级限流，小时请求额度却仍剩3520次。服务同时返回 `Retry-After: 60`、非零 `x-ratelimit-remaining` 和小时额度的 `x-ratelimit-reset`。旧代码无条件取两种等待时间的较大值，让收到二级限流的设备等待到主额度重置。自动观察及手动恢复均未成功；但200笔新增及其修改仍能在本机找到，没有伪报同步完成。

v1.3.4 仅在 `x-ratelimit-remaining: 0` 时使用主额度重置时间；二级限流仍遵守 Retry-After 及应用的失败退避策略。针对403、429的回归测试在修复前失败、修复后通过；同时验证主额度确实耗尽时仍等待重置。控制页面还验证了真实应用在二级限流后自动恢复、没有提前请求。

## 尚未解决：跨设备整条记录覆盖

跨司机编辑场景最终30笔齐全，所有设备也收敛，但8笔的上车或收款字段与业务操作意图不符。模拟实收从预期2280元变为2240元。它来自当前整条记录“较新修改覆盖旧修改”的合并规则：编辑备注时带着旧的上车/收款状态保存，会把别人的状态改动覆盖。手动再次同步无法恢复已经被覆盖的业务意图。

这不是记录条数检查能发现的问题。本轮没有改变合并协议；在完成字段级版本或服务端事务改造前，同一笔预约应尽量由一位司机负责编辑。司机可以共看台账和分别新增，但不能据此认为同时修改同一笔一定安全。

## 参数与结论的边界

配额默认取公开通用规则：5000 REST请求/小时，80内容写入/分钟，500内容写入/小时；另检查900端点积分/分钟和100并发。写入尝试（含冲突）保守计数，二级限制使用滑动窗口，其他项目使用均匀背景流量。这些是近似规则，不能复制 GitHub 未公开的动态风控，也不能据此宣称真实 GitHub 最多支持多少司机。[官方限额说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)、[官方最佳实践](https://docs.github.com/en/rest/using-the-rest-api/best-practices-for-using-the-rest-api)。

同一账号所属的个人令牌跨项目共享额度；多建仓库或多生成令牌不会增加该账号预算。多条专线还须分别设置数据仓库、本机存储键、离线缓存与应用身份。当前代码固定配置不能直接原样复制为另一条独立专线，详见 [实验室说明](SIMULATOR.md)。

每轮只执行一个固定随机种子，实际浏览器并发与网络完成顺序仍有变化。模拟耗时属于这台电脑，不能当作 GitHub 性能指标；未测试真实运营商网络、iPhone键盘、完整后台挂起或未公开服务风控。
